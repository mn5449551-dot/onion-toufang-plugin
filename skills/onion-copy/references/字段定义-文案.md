# 文案字段定义

> 写每套文案时严格按这份字段规则。字段名用原版（不简化）。
> **字数都是建议范围**，少了多了都 OK——唯一硬标准是**句子通顺自然**。

---

## 字段总览（按渠道 × 形式组合）

| 渠道 | 形式 | 必填字段 |
|---|---|---|
| 信息流 | 单图 | 主标题 + 副标题 |
| 应用商店 / 学习机 | 单图 | 主标题 + 副标题 |
| 应用商店 | 双图 | 短句1 + 短句2 |
| 应用商店 | 三图 | 短句1 + 短句2 + 短句3 |

> ⚠️ **不在该形式范围的字段直接不传**（写 Base 记录时不要传空字符串，省略字段即可）
> 信息流和学习机只支持单图（出图版位配置里没有它们的双/三图版位）；双图/三图仅应用商店可用。应用商店 / 学习机单图共用文案逻辑。

---

## 字段详细规则

生成文案前先做 `具体场景 + 具体情绪 + 产品动作 + 可感知变化` 自检。具体场景和情绪来自当前功能的真实使用场景；产品动作必须是洋葱真实能力；可感知变化只能写更清楚、更有方向、更容易继续学等可感知结果，不写绝对承诺。

产品动作词要做口径翻译：卖点库和方向卡里的能力描述（"AI 定制学习路径""补弱""精准补救"）是给 AI 理解功能用的内部口径，写进文案前必须换成学生话（"先补哪、每天学什么，洋葱帮你排好"）；替换表见 `渠道.md` 表达红线。

### 单图 / 双图 / 三图写法

字段结构、字数建议、双图/三图关系选择与正反例统一见 `规格.md` 对应章节，本文件不重复维护。写法底线不变：默认学生视角、有画面感、产品动作清楚、不要平铺直叙。

### 拍题精学“快查 + 深学”写法

当方向核心是“先快查，再按需深入问”时，文案要把两段逻辑写顺：

1. 先说明洋葱的快动作：`洋葱一拍，解析秒出` / `洋葱拍题精学，先出答案解析`
2. 再说明后续能力：`看不懂，再问洋葱 AI` / `卡在哪步，就继续追问`

好例子：

| 形式 | 文案 |
|---|---|
| 双图 | 图 1：洋葱一拍，解析秒出<br>图 2：看不懂，再问洋葱 AI |
| 双图 | 图 1：先看答案解析<br>图 2：卡在哪步，就继续追问 |
| 单图 | 主：拍题先看答案解析<br>副：洋葱一拍秒出，不懂还能继续问 AI |

坏例子：

| ❌ 文案 | 问题 | ✅ 改法 |
|---|---|---|
| 先看答案解析 / 洋葱不懂还能继续问 | “洋葱不懂”变成洋葱看不懂，主语错 | 洋葱一拍，解析秒出 / 看不懂，再问洋葱 AI |
| 拍题秒出解析 / 洋葱 AI 把步骤讲清楚 | 只有功能并列，少了“不只是快”的递进 | 洋葱一拍先出解析 / 卡在哪步，AI 接着讲 |
| 洋葱先给重点，再逐步讲 | “重点”太虚，不像具体产品动作 | 先看标准答案解析 / 不懂哪步，继续追问 |

## 文案类型（select 单选，可空）

| 类型 | 特征 | 例 |
|---|---|---|
| 钩子 | 疑问句 / 强吸引 | "拍了改、改了拍，识别不出来？" |
| 共情 | 描述用户处境 | "晚上 9 点作业还没写完？" |
| 数字 | 含具体数字 | "5 道题 1 分钟搞定" |
| 反差 | 对比类 | "拍三遍 vs 一拍精准" |
| 故事 | 场景叙事 | "考前最后两周，他这样翻盘..." |

AI 自选；模棱两可时留空即可。多套输出时不要全选同一类，类型覆盖门槛见 `规格.md` 多套生成。

### 渠道偏好

| 渠道 | 优先类型 | 少用类型 |
|---|---|---|
| 信息流 | 数字、钩子 | 故事、铺垫很长的共情 |
| 应用商店 / 学习机单图 | 数字、反差、学生视角共情、功能动作型钩子 | 家长共情、硬背书、过软故事 |
| 应用商店多图 | 排比、递进、动作过程型 | 三句孤立功能标签 |

类型选择逻辑整理自内部文案生成参考资料（仅维护人溯源），不新增 Base 选项。
