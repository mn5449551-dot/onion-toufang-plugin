# 文案渠道规范（信息流 / 应用商店 / 学习机）

> 出文案 skill 按当前渠道看对应章节。用户不指定人群时，**默认学生视角**；业务核心是 APP 图文，文案要让学生看见具体场景、具体问题和洋葱的产品动作。

## 全局心法

面向学生时，先做 `具体场景 + 具体情绪 + 产品动作 + 可感知变化` 的判断。学生第一视角不是强制写“我”，而是让学生看到自己的处境、语言和在意的结果。

| 目标 | 怎么写 |
|---|---|
| 锁定具体场景 + 具体问题 | 写出“晚上作业卡壳”“拍了三遍还不准”“看答案解析更懵”等能让学生觉得“是我”的瞬间 |
| 惊艳解法 | 用产品动作解释洋葱怎么解决：`洋葱一拍`、`洋葱拍题精学`、`分步解析`、`看不懂再问 AI`、`5-8 分钟动画课` |
| 场景奇效 | 写生活/情绪的具体变化：作业不再卡一晚、卡在哪步就问哪步、先测出薄弱点再学 |
| 产品锚定 | 每套文案至少让人知道“谁在解决、怎么解决”，避免只写“学习神器”“高效掌握” |

默认先建立 `具体场景 + 产品动作 + 可感知变化` 的理解，再按单图、双图、三图选择表达关系。`场景问题 -> 惊艳解法 -> 场景奇效` 是一种可用思路，不是所有文案的固定结构。

产品动作必须匹配当前功能：`30 分钟课堂`、`AI+真人答疑/辅导`、`先测再学/诊断分班` 是洋葱私教班、AI定制班的专属口径，只有当前功能是它们时才能写（功能边界详见 `../../../shared/references/creative-brief.md`）；拍题类文案的产品动作是 `洋葱一拍`、`分步解析`、`看不懂再问 AI`。

## 表达红线（运营反馈，表达层最高优先级）

与本文件或其他风格规则冲突时，按本节执行；用户明确要求的措辞除外。

**1. 场景要具体**：要有时间、动作、具体学习任务和卡住的瞬间，不能只贴"期末/暑假"节点标签。"暑假想补基础"不合格；"暑假想查漏补缺，一翻书直接懵了"合格。

**2. 学生话，不写产品腔**：下表左列默认不用，换成学生会说的话。卖点库和方向卡里的能力描述（如"AI 定制学习路径"）是给 AI 理解功能用的内部口径，写进文案前必须翻译。

| 默认不用（产品腔） | 换成（学生话） |
|---|---|
| 补弱 | 补短板、哪儿不会先补哪儿 |
| 学习路径、重点规划 | 先补哪、今天先学啥、每天学什么一眼清楚 |
| 高效学、精准补救 | 不绕弯、不白忙、越学越有方向 |
| 定制提分 | 按你的薄弱点排、哪儿丢分补哪儿 |

机械换皮无效：把"学习路径"改成"学习路线/学习地图"仍是产品腔。判断标准只有一个——学生口语里会不会这么说。

**3. 学生吐槽视角与网感**：广告要让学生觉得"这说的就是我"。共鸣来自语言身份认同——痛点句要写成学生自己会发的那条吐槽，而不是大人替学生总结的病情（"三科都有漏洞，先补哪个？"是诊断腔；"收藏从未停止，学习从未开始"才是学生的原话）。

- **痛点侧 = 学生在吐槽**：用学生真实的网络语言和梗自嘲，自带"期待 → 现实"的反差微叙事（立了 flag → 原地散架；这题我熟 → 一做全错），痛而好笑，不卖惨不恐吓。选梗的标准不是新潮，而是这个痛点发生时学生真的会用它自嘲——梗和痛点要天然一对（翻错题本 × 破防、囤资料 × 收藏从未停止），与痛点无关的热词硬塞只会尬。
- **解法侧 = 产品在接话**：大白话直给，一句说清产品动作；动作顺序必须符合真实使用流程，不跳步——要先测出弱在哪，才轮到补哪，不能直接写"先补最弱的那科"却不说怎么知道哪科弱。解法侧最多顺着痛点的梗接一下（"原地打转"→"不绕路"），不自己另起炉灶玩梗。**梗负责"像我"，直白负责"可信"，缺一边都不成立。**
- **梗有时效**：取材以用户/运营当下提供的案例和平台（抖音、B 站、微博等）的语感为准；过时的梗比没有梗更尬。

已验证的梗 × 痛点配对种子库（2026-06 收录，按需取用；梗会过期，运营给了更新案例就以新的为准；表外的梗不是禁区，按下方四个自检判断）：

| 梗 | 天然匹配的痛点 | 用例 |
|---|---|---|
| 立 flag / 原地散架 | 计划立了不执行 | 暑假 flag 立了一页，第三天集体阵亡？ |
| 收藏从未停止，学习从未开始 | 囤资料/囤课不学 | 直接可作主标题 |
| 三连：列了、贴了、忘了 | 列计划三件套落空 | 学习计划三连：列了、贴了、忘了 |
| 破防 / 破大防 | 翻错题本、看到分数 | 错题本一翻开，当场破大防 |
| 摆烂 | 坚持不下去、放弃 | 暑假一个人学，三天就摆烂 |
| 三分钟热度 | 学两天就凉 | 三分钟热度，学两天就凉 |
| 搭子 | 一个人学没伴（陪伴感场景） | 找洋葱 AI 当学习搭子 |
| 听劝 | 接受建议换方法（解法侧引导） | 听劝，用洋葱 AI 先测弱科 |
| 谁懂啊 | 求共鸣的吐槽开头 | 谁懂啊，错题本比暑假作业还厚 |
| 主打一个 | 自嘲式总结状态 | 主打一个想学，但不知道学啥 |
| 弯道超车 / 原地打转 | 想逆袭却没方向 | 暑假想弯道超车，结果在原地打转？ |
| 大眼瞪小眼 / 干瞪眼 | 对着题/答案没办法 | 错题和我，大眼瞪小眼 |
| vlog 体（起床、纠结、睡觉） | 一天啥也没干成 | 暑假学习 vlog：起床、纠结学哪科、睡觉 |
| 查了个寂寞 | 想查漏补缺没结果 | 别人查漏补缺，我查了个寂寞 |
| 汗流浃背 | 突然意识到问题严重 | 打开错题本，当场汗流浃背 |

出稿前四个自检问题（任一不过就改）：

1. 发布测试：痛点句学生会原样发到朋友圈/弹幕吗？
2. 朗读测试：大声读一遍顺不顺口？有没有要想一下才懂的词（解码成本高的梗、省主语的比喻）？
3. 逻辑测试：解法句的步骤顺序符合产品真实流程吗？有没有跳步？
4. 匹配测试：梗和这个痛点是天然一对，还是硬贴热词？去掉梗，句子还成立吗？

边界不变：每句的主语、动作、指代必须不靠脑补就明确（"三天就散了"不合格——散的是什么要猜）；具体画面优于抽象程度词（"计划列了一页"好于"计划列得满"）；整批全是平静疑问句 = 情绪不合格批次；网感和直白冲突时，直白优先。

**4. 陪伴感不是监督感**：写"卡住有人慢慢讲、不催不赶、可反复问、懂了再做下一题"；不写"老师盯着你/监督你完成/有人督促"。

## 信息流

> 信息流用户被动看到广告，需要强钩子打断浏览注意力，但仍要默认学生视角，不写成家长汇报或品牌宣传稿。
> 信息流只支持单图（主标题 + 副标题）；当前出图版位只有趣头条和网易的单图位，没有双/三图。

### 语气规则

| 特征 | 怎么写 |
|---|---|
| 钩子起手 | 主标题 = 学生当下痛点 + 明显情绪，用疑问 / 感叹，例如“拍了改、改了拍，识别不出来？”；不写说明句 |
| 情绪锚点 | 抓“卡壳 / 看不懂 / 懵 / 烦 / 作业还没写完”等情绪，写到位但不夸张（强度和零推断要求见「表达红线」） |
| 画面感 | 放进具体时刻：晚上 9 点、周末作业、考前两周、错题订正 |
| 产品动作 | 副标题 = 洋葱功能 + 解决动作，承接“用洋葱一拍、分步解析、看不懂再问 AI”，不只堆功能名 |

### 变体节奏

3 套以上时，主标题套路要拉开：

| 套 | 主标题套路 | 例 |
|---|---|---|
| 1 | 具体卡点 | 拍了改、改了拍，识别不出来？ |
| 2 | 反问质疑 | 看完答案解析更懵了？ |
| 3 | 时间压力 | 作业还剩亿点点？ |
| 4（可选） | 旧体验 vs 新解法 | 解析又长又没重点？ |
| 5（可选） | 情绪直给 | 一道题卡半小时，烦到想扔笔！ |

同批主标题不要全部用问号收尾，疑问 / 直给 / 感叹穿插。副标题可用承接解法、加细节、结果导向三类，但必须补足产品主体和产品动作，且同批副标题不要共用一个句式（落点轮换见 `规格.md` 多套生成）。

## 应用商店 / 学习机单图

> 应用商店和学习机的单图文案共用同一套逻辑：学生视角、口语化、有画面感、说清功能好在哪里。学习机只支持单图；应用商店保留单图、双图、三图。

### 共用单图写法

| 维度 | 规则 |
|---|---|
| 起手 | 可以直白，也可以痛点问句；不要太品牌腔 |
| 情绪 | 让学生觉得“这就是我现在遇到的问题”，情绪要写出来（懵、烦、卡住），不痛不痒不行；不是家长视角的省心宣传 |
| 画面 | 具体到作业、错题、课堂没听懂、考前复习、晚上无人答疑 |
| 产品动作 | 优先写当前功能真实的可感知动作：拍题类写“洋葱一拍”“洋葱拍题精学”“分步解析”；私教班/AI定制班才写“先测再学”“30 分钟课堂”“AI+真人答疑” |
| 结果 | 写“卡在哪步就问哪步”“薄弱点先测出来”“晚上难题不过夜”等具体变化 |

应用商店 / 学习机单图可展示为：

```markdown
**应用商店 / 学习机 · 单图**

| 编号 | 主标题 | 副标题 |
|---|---|---|
| 文案 1 | 收藏从未停止，学习从未开始 | 别囤了，洋葱 AI 挑出你真该学的那块 |
```

（示例解析：痛点句是学生原话级吐槽且与"囤资料不学"的痛点天然一对；解法句是产品直白接话。示例风格会过期，按运营最新案例校准，不照抄句式。）

### 私教班口径

涉及洋葱私教班时，读取 `../../../shared/knowledge/功能-洋葱私教班.md`。手册里的提分、100%紧贴校内大纲、4 周特训等表达可以作为业务口径吸收；不要把私教班事实误写到拍题精学里。

## 应用商店多图（双图 / 三图）

应用商店双图 = 两句前后关系；应用商店三图 = 三句节奏。结构、字数、关系选择与正反例见 `规格.md` 对应章节，本文件只管渠道侧要求：多图必须基于同一个单图核心卖点延展，不另起炉灶，不把多个功能硬拼在一起。

### 三图关系库

三图关系库共 8 类：`痛点 → 解法 → 奇效`、`动作 → 过程 → 结果`、`排比并列`、`旧方式 → 新方式 → 反差结果`、`场景 1 → 场景 2 → 场景 3`、`功能 1 → 功能 2 → 总结`、`问题 → 问题 → 统一解法`、`递进排比`。各类适用场景与示例见同目录 `规格.md` 三图章节；按方向心智选择，不要把某一类当成默认模板。

期末冲刺课表、定制课表、私教班备考计划这类方向，优先考虑三类：`痛点 → 解法 → 奇效`、`旧方式 → 新方式 → 反差结果`、`递进排比`。这三类既适合三图，也最能把“不是让你更努力，而是帮你学得更准”讲出来。

至少图 2 或图 3 出现“洋葱/洋葱学园”或明确产品动作，避免用户看完记不住是谁在解决问题；仅当整组短句是连续的“你→你→你”命令式贯通时可豁免——商店多图画面本身带洋葱 Logo/IP 等品牌元素，品牌识别由画面承担。

## 避免的写法

| 避免 | 为啥 |
|---|---|
| `K12 学生必备` | 太泛，没有学生画面感 |
| `高效学习神器` | 空泛，没说产品动作 |
| `妈妈省心，家长放心` | 默认学生视角下会变成家长腔 |
| `题不会做 / 拍一下 / 当场会` | 用户记不住“谁在解决”和“怎么解决” |
| 把私教班卖点写进拍题精学 | 产品事实错位 |

## 学段语气

- 小学高年级：可以更轻松、趣味。
- 初中：直接，允许一点同侪感。
- 高中：平等、干货，不哄人。
- 中职：务实，围绕职教高考、对口升学、技能证等路径。
